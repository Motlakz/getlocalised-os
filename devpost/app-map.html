GetLocalised OS

An open-source localization agent: an English Google Play listing goes in, and a native listing for French, Spanish or German comes out, shaped by skill files and checked against the store. One Next.js app with two pages (landing and Playground), one engine, and committed example data.

A reference route (three stops)

Search for the anchor in each file. This route is for reference; it wasn't toured live.

  1. components/playground/command-menu.tsx · search export function CommandMenu
    The / palette. A picked command renders PreviewView, which calls load(): simulateRun for a prepared result (with the short running state you asked for) or runLive with a key. Nothing is applied until Apply.
  2. lib/engine/localize.ts · search export async function rewriteField and const DEMAND_CLAIM
    The engine: builds the prompt, validates the JSON with zod, then does one corrective retry if a preview breaks the limit or a note claims search demand. Any claim still left is dropped.
  3. components/playground/state.ts · search export function playgroundReducer
    Applying a preview is one "apply" action: it replaces that field, records the command, and keeps the preview's notes. The findings then recompute from the new text. Covered by state.test.ts.

A practice to reuse: turn a rule into a check that fails

What happened. The PRD required a note saying the wording is "not measured search volume" (prd.md > Native Listing and Compare View). During slice 5's live check, the model wrote "a high-volume search term", and 38 prepared notes made similar claims. A prompt rule alone brought that down to 17, not zero.

What fixed it. The rule became code: DEMAND_CLAIM in lib/engine/localize.ts triggers a corrective retry and drops what's left, and scripts/validate.ts fails on any claim. bun run validate now reports 9 of 9 seed files clean. The same pattern caught over-limit descriptions and an unaccented French title ("Jeune" for "Jeûne").

Reuse it. When an agent's output has to satisfy a rule (truthfulness, a length, a format), don't rely on the instruction alone. Write the rule as a check that runs every time and fails loudly, then let the agent retry against it.

Run it again

bun install
bun dev --port 3100          # landing: http://localhost:3100 · Playground: /playground
bun test && bun run validate  # findings + reducer tests, seed data checks
bun run localize --app bellyclock --to de-DE   # local run (needs GEMINI_API_KEY in .env.local)
