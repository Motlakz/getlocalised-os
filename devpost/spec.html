GetLocalised OS: Technical Spec

One Next.js app, two pages, one engine. Seeded JSON makes the Playground work with no key; the same engine runs live with a visitor's key and locally with yours.

status: approved

Architecture

No database, no accounts, and no production secrets. The only outside services are the user's chosen model provider and, at build time only, Google Play.

RISKS Failure modes and fallbacks
  • Bad key / out of credit: a plain message in the menu; the field is unchanged and seeded mode still works
  • Malformed model output: zod rejects it, one retry, then a clear error. Over-limit output is labelled, and Fit the limit is suggested
  • Scraper breaks: only affects the build-time run. Hand-curated phrases are labelled “Curated by the author”
  • Gemini free-tier limits during the seed run: back off, stop cleanly, resume
SIMPLIFIED What was simplified and why
  • JSON in the repo instead of a database
  • Build-time scraping instead of live fetch
  • One preview per seeded command (~144 seed calls)
  • A Bun script instead of a published CLI
  • Deterministic findings instead of model-judged ones
  • Read-only skills in the Playground
CHECK Verify early in the build
  • Current Gemini and OpenAI model IDs and structured-output options
  • google-play-scraper app() and suggest() still work
  • Next 16 route handler conventions (bundled docs)
  • The useful unknown, “will the key work?”: one live Simplify run in the deployed Playground, with the key absent from logs and responses
