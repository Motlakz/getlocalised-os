GetLocalised OS

An open-source localization agent for mobile apps. It turns one Play Store listing into a native listing for another market, guided by skills you can read and edit.

status: approved
The kernel: native, not translated, shaped by skills you can see.

The output keeps the original meaning in the words people in that country actually search with. Plain skill files (brand, audience, store rules, ASO guidance) shape it, and the developer can open them, edit them, and run again.

How it fits together

What “working” looks like

A hosted Playground that a judge can open with no setup and no key.

The “oh, that’s cool” beat: edit a skill (e.g. the brand/audience rules), run again, and watch the listing change. Then paste your own API key and run the same flow live.

Who it’s for

The person

A solo developer shipping several apps in several languages and regions.

Today

Updates each Play Store listing by hand, language by language, asking an AI model about each line one at a time. Wants that work cut in half.

Identity

The original GetLocalised Slate design (near-black ink, sage greys, Raleway headings / Source Sans body / Merriweather serif) in greyscale instead of lime. It is a separate species with a family resemblance, shared by the landing page, Playground, and README.

Boundary

NOW The proof of concept
  • Hosted Playground, the main surface
  • Minimal landing page for dev.getlocalised.com (what it is, into the Playground, GitHub), same deploy
  • README styled to match: banner, clear structure, greyscale identity
  • Example apps: the author’s real listings as fixtures, with a predefined category and search flow, so the demo is deterministic without a key
  • “Paste your own listing” for any other app
  • Target-language selection and native generation of Play Store metadata
  • Visible, editable skills that feed the generation
  • BYOK live mode; keys are never stored server-side
  • Play Store character-limit validation and basic quality checks
  • Copy and export only
LATER Worth doing, not now
  • CLI: getlocalised localize --from en-US --to de-DE,fr-FR using .getlocalised/skills + getlocalised.config.ts, running locally
  • Screenshot localization, added as the open-source edition grows
  • Fetching any app live by package ID or store URL (no official public Play API, so it needs a deliberate data-source choice)
  • App Store (iOS) metadata
  • Remaining dev-site sections: Docs, Skills, CLI, Examples, Self-hosting
CUT Out of scope
  • Measured search volume, keywords, competitor/market intelligence, ranking and opportunity scoring: these need data infrastructure outside this project’s purpose. Native wording comes from the model plus your skills.
  • Store upload and publishing via Play Console: credentials are sensitive, so copy/export keeps the developer in control of their keys
  • Mentioning any other edition in the product: this project stands alone (the README’s prior-work disclosure still names related work, as the rules require)
  • Code, prompts, or data from other projects: anything actually reused, including design tokens, is listed in the README’s prior-work table
